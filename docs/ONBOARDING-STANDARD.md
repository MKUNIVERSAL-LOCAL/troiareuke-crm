# 신규 지점(계정) 온보딩 표준 운영 절차

> 2026-07-27 오너 지시: "아르케스파뿐만 아니라 앞으로 추가되는 계정도 동일하게 운영한다."
> 모든 지점 계정은 이 문서의 절차를 따른다. 지점별 예외 운영 금지.

## 운영 원칙

1. **중앙 저장소는 NAS 단일** — 모든 지점 데이터는 `https://crm-api.mkcorp.familyds.com`(NAS auth-api + Postgres)에 쌓인다. Supabase·로컬 전용 빌드를 신규 지점에 배포하지 않는다.
2. **계정은 발급제** — 공개 가입 차단(`ALLOW_PUBLIC_SIGNUP=false`). 계정 생성은 슈퍼어드민만 한다.
3. **배포 exe는 항상 NAS 빌드** — 빌드 머신 `.env`에 `VITE_AUTH_API_URL=https://crm-api.mkcorp.familyds.com` 필수, `.env.local` 존재 시 빌드가 의도적으로 실패한다(오염 가드). 값이 빠진 exe는 로컬 폴백 모드가 되므로 배포 금지.
4. **통계는 어드민에서** — 지점 데이터는 자동으로 `/api/admin/analytics` 집계에 포함된다. 지점 추가를 위한 통계 측 작업은 없다.

## 온보딩 절차 (지점 1곳 기준, 약 30분)

### 1. 계정 발급 (본사)
- 슈퍼어드민 exe → 지점 관리 → 계정 발급.
- 임시 비밀번호는 **1회만 표시**되므로 즉시 안전한 채널로 지점에 전달한다.
- 지점명·연락처 등 기본 정보를 정확히 입력한다(향후 본인확인·통계 표시에 사용).

### 2. 프로그램 설치 (지점 PC)
- OneDrive `CRM-사용자배포용` 폴더의 최신 exe를 지점 PC에 설치한다.
- 전달 전 `_deployment-version.txt`로 최신 버전인지 확인한다.

### 3. 로그인 및 초기 설정
- 발급 계정으로 로그인 → 온보딩 완료 → 비밀번호를 임시비번에서 변경하도록 안내한다.

### 4. 기존 데이터 이관 (해당 시)
- 같은 PC에서 구버전(로컬/베타)을 쓰던 지점만 해당.
- 설정 → 데이터 백업 → **[기존 계정 데이터 가져오기 (중앙 서버 이관)]** 실행.
  - 이 버튼은 NAS 빌드이면서 이관 후보 데이터가 있을 때만 표시된다.
  - 현재 계정에 이미 있는 데이터는 덮어쓰지 않는다. 실행 후 앱이 재시작되며 서버로 업로드된다.

### 5. 개통 검증 (필수 — 이 3개 통과 전에는 개통 완료로 보고하지 않는다)
1. 지점 PC: 테스트 고객 1건 등록 → 저장 확인.
2. 본사 어드민: 통계 화면에서 해당 지점 선택 → 고객 수에 반영 확인 (= NAS 저장 검증).
3. 이관을 했다면: 고객·예약·결제 건수가 구버전과 일치하는지 표본 확인.

### 6. 구버전 정리
- 검증 통과 후 구 프로그램 제거(제어판 → 프로그램 제거). 이관 검증 전에는 제거하지 않는다.

## 운영 중 대응

| 상황 | 대응 |
|------|------|
| 비밀번호 분실 | 슈퍼어드민 exe → 사용자 관리 → 비밀번호 재설정(임시비번 발급). 셀프 재설정(본인확인+승인 방식)은 도입 예정 |
| 지점 인터넷 장애 | 입력은 로컬에 임시 저장되나 **장애 중 입력분은 유실 위험이 있음**(outbox 보강 전). 장애 복구 전 대량 입력 자제 안내 |
| 지점 계약 종료 | 슈퍼어드민 → 계정 비활성화. 데이터는 삭제하지 않고 보존(백업 정책 준수) |
| 데이터 백업 | 서버가 매일 04시 지점별 JSON+사진을 `/volume1/CRM-BACKUP`에 자동 내보내기(14일 보관). 별도 조치 불필요 |

## 서버 측 지점 추가 작업

**없음.** 계정 발급만 하면 데이터 스코프(지점별 격리)·통계 집계·백업이 자동 적용된다. 서버 재배포는 기능 변경 시에만 `docs/NAS-REDEPLOY-RUNBOOK.md` 절차로 수행한다.
