# 고객 포털·온라인 예약 설계 (169, 2026-11-24 — GAP C-10·R-6, 서버는 승인 B-2 뒤)

> 목적: 고객이 매장 PC 없이 **자기 예약·회차권 잔여·광고 수신 동의**를 보고, **예약 요청**을 넣는 공개 화면. 143(예약 요청함·공개 슬롯 규칙)·155(동의 태그)·166(세그먼트)과 이어진다. 서버 공개 라우트·OTP 발송(SOLAPI, C-2)이 필요해 **설계와 순수 규칙(`portalRule.ts`)까지만** 코드에 넣고, 화면·서버는 승인 뒤 2 묶음으로 만든다.

## 1. 범위(1차)
| 기능 | 고객이 하는 일 | 지점 PC 에서 보이는 것 | 기존 모듈 |
|---|---|---|---|
| 예약 요청 | 날짜·시술·희망 시각 선택 → 요청 | 예약 요청함(143)에 도착 → 직원이 예약으로 등록/거절 | `publicSlotsRule`(가용 시작 시각), `bookingRequests` |
| 내 예약 보기·변경 요청 | 다가오는 예약 확인, 변경·취소 **요청**(직접 변경 아님) | 요청함에 "변경 요청" 유형 | `bookingRequests` 유형 추가 |
| 회차권 잔여·만료 | 프로그램명·남은 회차·만료일 | 없음(읽기) | `programLedgerRule` 잔여 |
| 광고 수신 동의 | 동의/철회, 채널 선택 | 고객 태그(155)에 반영 → 캠페인 대상에서 즉시 제외 | `consentRule`·`marketingConsent` |
| 개인정보 | 보유 항목 열람, 삭제 요청 | 요청함 "삭제 요청" → 관리자가 익명화(P4) | `retentionPolicy` 익명화 |

2차(별도 승인): 선결제·예약금(PG C-4), 리뷰·후기, 사진 비교(Before/After) 열람.

## 2. 인증 — 전화번호 + 일회용 번호(OTP)
- 고객 식별은 **지점 + 전화번호**(CRM 고객의 phone 정규화와 같은 `normalizePhone`). 비밀번호 없음.
- OTP: 6자리 숫자, **5분** 유효, 재요청 **60초** 간격, 연속 **5회 실패 시 15분 잠금**, 성공 시 세션 토큰(지점·고객 id·만료 24시간, 서버 서명). 규칙은 `portalRule.ts`(순수)에 두어 서버·테스트가 같은 값을 쓴다.
- OTP 발송은 SOLAPI(C-2) 문자 — 발송 비용 건당. 미계약이면 포털은 **"준비 중"** 만 보이고 어떤 자료도 보여주지 않는다(가짜 성공 금지).
- 전화번호가 CRM 에 없으면 "등록되지 않은 번호" — 가입은 포털에서 하지 않는다(지점이 등록). 번호 존재 여부 노출을 막기 위해 응답 문구·지연을 같게 한다.

## 3. 서버(161 뒤, 승인 B-2) — `server/src/portal/*`
| 메서드 | 경로 | 설명 | 보호 |
|---|---|---|---|
| GET | `/book/:branchSlug` | 공개 예약 페이지(정적 번들) | 공개, slug 는 지점 설정에서 발급 |
| GET | `/api/public/:branchSlug/slots?date=&serviceId=` | 가용 시작 시각 — `publicSlotsRule` + 직원 근무표(141) + 자원(142) | rate limit 60/분/IP, 캐시 30초 |
| POST | `/api/public/:branchSlug/booking-requests` | 예약 요청(이름·전화·시술·희망 시각·메모) → `booking_requests` 컬렉션 | rate limit 5/시간/전화, 캡차 없음(문자 OTP 가 대체) |
| POST | `/api/portal/:branchSlug/otp` · `/verify` | OTP 발송·검증 → 세션 토큰 | `portalRule` 정책, 잠금 테이블 |
| GET | `/api/portal/me` | 내 예약(오늘부터 30일 뒤까지, 양끝 포함)·회차권 잔여·동의 상태 | 세션 토큰 |
| POST | `/api/portal/me/consent` | 동의/철회(채널) → 고객 태그 갱신(서버가 `tagsWithConsent` 로) | 세션 토큰 |
| POST | `/api/portal/me/requests` | 변경·취소·삭제 요청 → 요청함 | 세션 토큰 |
서버 컬렉션: `booking_requests`(143 어댑터 계약 그대로), `portal_otp`(해시·만료·실패 수), `portal_sessions`. 고객 PII 는 세션 범위 밖으로 나가지 않는다(지점 전체 목록 API 없음).

## 4. 화면(공개 번들, 지점 앱과 분리)
- `/book/:branchSlug`: 매장 이름·영업시간 → 날짜 → 시술 → 시각(가용만) → 이름·전화 → 요청 완료("직원 확인 뒤 확정 문자").
- `/portal/:branchSlug`: 전화 → OTP → 내 예약 / 회차권 / 수신 동의 / 개인정보.
- 접근성·모바일 우선(a11y 게이트 동일 기준), 폰트 Pretendard, 한국어.

## 5. 보안·개인정보
- 공개 API 는 지점 slug 로만 식별(branch_id 비노출), 응답에 다른 고객 자료 없음, 요청 본문 길이 제한, 로그에 전화번호 마스킹.
- OTP 해시 저장, 세션 24시간, 토큰 폐기 API. 모든 쓰기는 "요청" 이고 지점 직원이 확정한다(고객이 CRM 레코드를 직접 바꾸지 않음) — 동의 철회만 즉시 반영(법적 의무).
- 개인정보 처리방침 링크·동의 체크(요청 시) 필수.

## 6. 승인·전제
- **B-2** 서버 공개 라우트·컬렉션 3개 배포, **C-2** SOLAPI(OTP·확정 문자), 지점 slug 발급 UI(어드민, 비코어), 공개 번들 호스팅(NAS 정적 — B-7 와 같은 배포 경로).
- 비용: SOLAPI 건당 발송료(OTP 1건 + 확정 1건/예약). 미승인 시: 포털 없음, 요청함은 수기 접수(143)로 유지.

## 7. 코드로 들어간 것(169)
- `src/lib/portalRule.ts`(순수): OTP 정책 상수, `requestOtp`/`verifyOtp`(발송·검증·잠금 전이), `isValidOtpCode`, `portalSummaryOf`(고객 사실 → 포털에 보일 항목만 — 이름·다가오는 예약·회차권 잔여·동의 상태, 주소·메모·매출 제외). lib-units 스펙.
- 화면·서버는 승인 뒤: 170(공개 예약 페이지 + 슬롯 API) → 171(포털 OTP·내 예약·동의).
