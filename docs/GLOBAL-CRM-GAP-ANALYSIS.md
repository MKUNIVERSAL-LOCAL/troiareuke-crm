# 글로벌 CRM 대비 기능 GAP 분석 (GLOBAL-CRM-GAP-ANALYSIS)

작성 2026-11-24 (마스터 프롬프트 08절). 근거: 기존 기능 전수 조사(코드 기준, HEAD 698565f~57077fc)와 오픈소스 8종 검증(`THIRD-PARTY-CODE-REGISTER.md`). 상용 CRM(Fresha·Zenoti·Boulevard·Mindbody·Vagaro) 공개 정보 벤치마크는 별도 에이전트 결과로 보강한다(갱신 예정 표시).

상태 분류: ✅ 구현·정상 / 🔧 구현됐으나 개선 필요 / ◐ 일부 구현 / ✗ 미구현 / 🔒 외부 계약·API 권한 필요 / ⛔ 현 구조상 부적합.
열 설명: 위치=현재 구현 파일, 참고=참고 솔루션(분류 A/B/C — 등록부), 영향=기존 기능 영향도, 가치=사용자/사업 가치(상·중·하), 작업량=묶음 수(1묶음 ≈ 구현+게이트+기록 반나절), 승인=오너 승인 필요 여부, 완료 기준=테스트 가능한 조건.

## 0. 구조 전제(모든 항목에 공통)
- 데이터 계층 코어(`store.ts`)는 잠금 → 신규 기능은 비코어 파생 모듈(`programSessions`·`customerStats` 방식)과 서버 API 로 구현. 코어 필드 추가가 필요한 것은 승인 대기열 A.
- 서버는 `crm_records(branch_id, collection, id, data JSONB)` 단일 테이블 + 전 컬렉션 전체 로드. 수천 건 규모까지는 동작(scale E2E: 고객 2,000·시술 6,000·예약 3,000·결제 4,000). 서버 페이징·집계·제약은 없음 → PHASE 1~2 에서 서버 측 보강(승인 B-2).
- 단위 테스트 프레임워크 없음(순수 모듈은 Playwright `lib-units`), 서버 자동 테스트 0건 → 품질 항목 참조.
