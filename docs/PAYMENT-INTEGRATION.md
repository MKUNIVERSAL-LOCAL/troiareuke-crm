# 결제(카드·무통장입금) 연결 가이드 — 토스페이먼츠

> 상태: **연결 직전까지 개발 완료** (2026-08-04, 오너 지시).
> 코드는 전부 배포되어 있고, 아래 **PG 키 2개를 NAS 서버 .env에 넣는 순간 활성화**됩니다.
> 키가 없는 동안에는 지점 화면에 "온라인 결제 준비 중"으로 정직하게 표시됩니다 (가짜 성공 없음).

## 동작 구조 (이미 구현됨)

```
지점 CRM (매출·손익 관리 > 결제 요청)
  → 결제 링크 생성 (POST /api/payments/requests)
  → 링크를 고객에게 문자/카톡으로 전달
고객 휴대폰/PC 브라우저
  → https://crm-api.mkcorp.familyds.com/pay/<id>  (NAS가 호스팅하는 결제 페이지)
  → [카드로 결제] 또는 [무통장입금(가상계좌)] → 토스페이먼츠 결제창
  → 성공 리다이렉트 → 서버가 토스 승인 API(confirm)로 최종 확정
NAS 서버
  → 카드: 즉시 결제 완료 처리
  → 가상계좌: 계좌 안내 표시 → 입금 웹훅 수신 시 완료 처리
  → 완료 시 해당 지점 매출(crm_records payments)에 자동 기록
     (지점 CRM에는 재시작/다음 동기화 때 "온라인 결제" 매출로 표시)
```

- 시크릿 키는 **서버(.env)에만** 존재. 클라이언트/exe에는 어떤 키도 들어가지 않음.
- Electron 앱에서 결제창을 띄우지 않고 외부 브라우저(고객 휴대폰)에서 결제하므로
  코어(main.cjs/CSP) 수정이 전혀 필요 없음.
- 금액 검증: 요청 금액과 승인 금액 불일치 시 승인 거부. 가상계좌 웹훅은
  secret 대조 + 토스 API 재조회 이중 검증 (웹훅 본문을 신뢰하지 않음).

## ⚠️ 계약 전에 먼저 정할 것 — 정산을 누가 받는가

현재 구현은 서버 `.env`에 **키 한 쌍(TOSS_CLIENT_KEY/SECRET)** 만 두는 구조다.
즉 **모든 지점의 고객 결제가 그 계약 명의의 계좌로 정산된다.**

| 방식 | 계약 | 정산 | 우리 코드 |
|---|---|---|---|
| **A. 본사 일괄** | 본사(MK Corp) 1건 | 전 지점 결제금이 본사 계좌로 → 본사가 지점에 정산 | **지금 그대로 동작** |
| **B. 지점별** | 지점 사업자마다 각각 | 각 지점 계좌로 직접 | **미구현** — 지점별 키 저장(auth_users 컬럼) + 요청 시 지점 키 선택 로직 추가 필요 |

- 지점이 남의 사업자 명의로 카드 매출을 올리면 **세무상 매출 귀속이 어긋난다.**
  각 지점이 독립 사업자라면 원칙적으로 **B(지점별 계약)** 가 맞다.
- B로 갈 경우 토스페이먼츠의 **파트너(서브몰) 구조**를 함께 문의할 것. 지점 수가 늘면
  본사가 대표 계약을 맺고 하위 상점을 등록하는 방식이 관리가 쉽다.
- **A로 먼저 시작(파일럿 1~2개 지점) → 검증 후 B로 확장**도 가능하다. 그 경우
  지점별 키 저장 기능을 추가 개발하면 되고, 결제 페이지·승인·매출기록 로직은 그대로 재사용된다.

## 연결 절차 (오너가 할 일)

### 0. 사전 준비물
| 구분 | 준비물 |
|---|---|
| 공통 | 사업자등록증(사본), **정산받을 사업자 명의 통장 사본**, 대표자 신분증 사본 |
| 개인사업자 | 위 + 대표자 인감증명서(3개월 이내), 대리 신청 시 위임장 |
| 법인사업자 | 위 + 법인등기부등본·법인인감증명서(각 3개월 이내, **제출용**, 뒷장까지 전부) |
| 온라인 결제 | **통신판매업 신고증** — 결제 링크는 온라인 결제라 요구될 수 있음. 미신고면 관할 구청/정부24에서 먼저 신고(사업자등록증 + 구매안전서비스 이용확인증 필요) |

> 서류는 **3개월 이내 발급본**이어야 반려되지 않는다. 미리 떼어두면 심사가 빨라진다.

### 1. 토스페이먼츠 가맹 계약
1. https://www.tosspayments.com → **전자결제 신청** (상점관리자에서 본인인증 후 신청서 제출)
2. 신청서에 **이용할 결제수단으로 `신용카드`와 `가상계좌(무통장입금)` 를 반드시 함께 체크**
   — 가상계좌를 빠뜨리면 무통장입금 기능이 동작하지 않는다.
3. 약 3영업일 내 계약부서 안내 메일 수신 → 위 서류 제출 + 계약서 작성
4. **카드사 심사**: 카드사별로 진행되어 계약 완료 후 **통상 2주** 소요
   (심사 중에는 테스트 키로 미리 전체 흐름을 연습할 수 있다 — 아래 5단계 참고)
5. 심사 완료 후 [개발자센터 > API 키]에서 **라이브 키** 확인:
   - 클라이언트 키: `live_ck_...`
   - 시크릿 키: `live_sk_...`
   - ⚠️ 우리 시스템은 **API 개별 연동 키(`sk`)** 를 쓴다. 결제위젯 키(`gsk`)가 아니다.
   - ⚠️ 시크릿 키는 절대 카톡·메일·깃허브에 올리지 말 것. 서버 `.env`에만 넣는다.

### 2. NAS 서버에 키 등록
DSM SSH 또는 File Station에서 `/volume1/docker/troiareuke-crm-server/.env`에 추가:

```env
TOSS_CLIENT_KEY=live_ck_여기에_클라이언트키
TOSS_SECRET_KEY=live_sk_여기에_시크릿키
# 선택: 결제 링크 유효시간(시간, 기본 72)
# PAY_REQUEST_EXPIRE_HOURS=72
```

적용: **`docker-compose up -d`로 재생성해야 한다** (단순 restart는 새 환경변수를 읽지 않음):

```sh
cd /volume1/docker/troiareuke-crm-server
/usr/local/bin/docker-compose -p troiareuke-crm up -d
```

DSM 작업 스케줄러의 `CRM-server-update` 작업을 한 번 실행해도 동일하게 적용된다.
(compose 파일이 TOSS_* 변수를 컨테이너로 전달하도록 되어 있는지는 server/docker-compose.yml 참고 —
전달 목록에 없으면 .env에 키를 넣어도 서버가 못 읽어 계속 "준비 중"으로 보인다.)

### 3. 토스 개발자센터에 웹훅 등록 (가상계좌 입금통지)
- [개발자센터 > 웹훅] → 웹훅 URL 등록:
  `https://crm-api.mkcorp.familyds.com/api/payments/webhook`
- 이벤트: **가상계좌 입금 (DEPOSIT_CALLBACK)**

### 4. 개통 검증 (키 등록 후 5분)
1. 지점 CRM → 매출·손익 관리 → [결제 요청] 버튼이 "준비 중"에서 활성으로 바뀌었는지
2. 1,000원 테스트 결제 요청 생성 → 본인 휴대폰으로 링크 열어 카드 결제
3. 결제 완료 페이지 확인 → 어드민 통계 또는 지점 매출 목록(재시작 후)에
   "온라인 결제(카드)" 1,000원 기록 확인
4. 테스트 건은 토스 상점관리자에서 결제 취소(환불) 처리
5. 가상계좌도 동일하게 1회: 발급 → 입금 → 자동 완료 확인 (웹훅 검증)

### 5. 환불은 현재 토스 상점관리자에서 (앱 내 환불 미구현)
결제 링크로 받은 건을 환불할 때는 토스 상점관리자에서 취소한 뒤,
지점 CRM의 매출 관리에서 해당 "온라인 결제" 기록을 환불 상태로 바꿔주세요.
(앱에서 버튼 한 번으로 환불하는 기능은 실사용 데이터가 쌓인 뒤 추가 예정 — 지금 만들면
검증되지 않은 자동 환불 경로가 생겨 위험합니다.)

### 6. 심사 대기 중 미리 연습하기 (권장)
라이브 키 대신 **테스트 키(`test_ck_...` / `test_sk_...`)** 를 넣으면 실청구 없이
전체 흐름을 그대로 돌려볼 수 있다. 개발자센터 가입만 하면 계약 전에도 발급된다.
카드사 심사 2주를 기다리는 동안 지점 교육·화면 확인을 끝내두면 개통일에 바로 쓸 수 있다.
연습이 끝나면 라이브 키로 교체 후 `docker-compose up -d` 재실행.

## 수수료·정산 참고
- 카드 수수료율은 **가맹점 등급(영세/중소1~3/일반)** 에 따라 다르다. 등급은 국세청 매출 기준으로
  자동 산정되며, 신규 사업자는 잠정 등급이 적용됐다가 나중에 소급 정산된다.
  정확한 요율은 계약서에 명시되므로 **계약서를 받고 반드시 확인할 것.**
- 가상계좌는 보통 건당 정액 수수료.
- 정산 주기(D+n)·정산 계좌는 토스 상점관리자에서 확인·설정.
- 보증보험 가입이 요구될 수 있다(계약 단계에서 안내됨).

## 자주 막히는 지점 (미리 알아두기)
| 증상 | 원인 | 조치 |
|---|---|---|
| 키를 넣었는데 계속 "준비 중" | compose가 TOSS_* 를 컨테이너에 전달 안 함 / restart만 함 | `docker-compose up -d`로 재생성 |
| 무통장입금 버튼만 실패 | 계약 시 가상계좌 미신청 | 토스에 가상계좌 추가 신청 |
| 입금했는데 매출에 안 잡힘 | 웹훅 URL 미등록 | 3단계 웹훅 등록 확인 |
| 결제창이 안 열림(고객 폰) | 고객 네트워크에서 토스 SDK 차단 | 화면에 안내 문구가 뜨도록 처리됨 — 다른 망에서 재시도 |
| 카드 결제는 되는데 승인이 지연 | 토스 API 지연 | 15초 타임아웃 후 안내 표시, 중복 결제는 발생하지 않음 |

## 서버 API 요약 (구현 완료)
| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/payments/pg-config` | 활성화 여부 (지점 세션) |
| POST | `/api/payments/requests` | 결제 요청 생성 (1,000원~1억, 지점 스코프) |
| GET | `/api/payments/requests` | 요청 목록 (최근 100건) |
| POST | `/api/payments/requests/:id/cancel` | 대기 건 취소 |
| GET | `/pay/:id` | 고객용 결제 페이지 (공개, noindex) |
| GET | `/pay/:id/success` · `/pay/:id/fail` | 결제창 리다이렉트 처리 (서버 승인) |
| POST | `/api/payments/webhook` | 가상계좌 입금통지 (secret+API 재조회 검증) |

## 참고: 기존 구독 결제(payment.ts)와의 관계
- `src/lib/payment.ts`(코어)의 아임포트 구독 결제는 **본사 → 지점 구독료** 용도로 별개이며,
  `PAYMENT_ENABLED=false` 런치 게이트가 그대로 유지된다 (이번 작업과 무관).
- 이 문서의 결제 링크는 **지점 → 고객 수납** 용도다.
