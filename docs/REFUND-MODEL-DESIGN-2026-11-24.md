# 환불 모델 설계서 (148, GAP P-3, 오너 결정 #9)

작성 2026-11-24 · 상태 **결정 대기(D-9)** · 결정 뒤 구현 1 묶음(비코어, 코어 변경 없음)

## 1. 왜 결정이 필요한가
지금(모델 A)은 환불을 **원 결제의 상태를 `refunded` 로 뒤집어** 처리한다. 그 결제가 속한 달 매출이 소급해서 줄고(지난달 마감 숫자가 바뀜), 부분 환불이 없고(전액뿐), 환불일은 memo 태그(`[환불 YYYY-MM-DD]`)로만 남는다. 8차 금액 감사(11-20)가 지적한 사례: 10회 500,000원(10/5 결제) 4회 사용 뒤 11/15 에 300,000원 부분 환불 → A 에서는 10월 매출 500,000원이 통째로 사라지고 실제 받은 200,000원은 어디에도 없다(부가세 신고분과 불일치). 147 의 **월 마감 잠금**이 들어온 지금은 A 와 충돌한다 — 마감한 달의 결제를 환불하려면 마감을 풀어야 하고, 풀면 신고 숫자가 바뀐다.

## 2. 두 모델
| | A 상태 뒤집기(현행) | B 환불일 기준 음수 결제 행(권장) |
|---|---|---|
| 원 결제 | `status: refunded` 로 변경 | 그대로(완료) |
| 환불 기록 | 없음(원 결제 1행에 흡수) | **새 행** `{ type: 원 결제 type, amount: −환불액, status: completed, paymentDate: 환불일, referenceId: 원 결제 referenceId, memo: "[환불 처리일 ← 원결제일 원결제id] 사유 · 처리자" }` |
| 월 매출 영향 | 원 결제월이 소급 감소 | 환불한 달에서 차감(Σ amount) — 지난달 마감 불변 |
| 부분 환불 | 불가 | 가능(원 결제액 − 기존 환불 ≤) |
| 사유·처리자 | 없음 | memo 에 남음 |
| 집계 코드 변경 | 없음 | **없음** — 매출·손익·대시보드·마감 요약·엑셀·직원 실적·고객 누적액이 전부 Σ amount 라 음수 행이 그대로 차감된다. 서버 어드민 집계도 `AMOUNT` 정규식이 `-?\d+` 로 음수 허용 |
| 화면 변경 | — | 결제 수정 > "환불" 을 **환불 행 만들기**로(금액·환불일·사유 입력), 목록에 환불 행 배지, "이달 환불 처리 N원" 보조행을 환불 행 합으로 |
| 옛 데이터 | — | 옛 `refunded` 행은 읽기 호환 그대로(매출에서 제외 유지). 이관 없음 — 새 환불부터 B |
| 회차권 | 전액 환불 때 회차권 종료 | 부분 환불도 가능 — 제안액 = 잔여 회차 × 회당 가격 × (1 − 위약금율), 전액이면 회차권 종료(완료 처리 + notes 줄) |
| 제품 | 판매 취소에서만(재고 복구와 함께) | 동일 — 판매 취소가 환불 행을 만든다(재고 복구 + 음수 행) |
| 코어 | 없음 | 없음(Payment 필드 추가 불필요) |

## 3. 음수 금액 가정 점검 (코드 전수, 11-24)

## 4. 구현 순서(결정 뒤, 1 묶음)
1. `refundRule.ts`(148 에서 준비, 순수·스펙 고정) 를 매출 > 결제 수정 > [환불] 에 연결 — 금액(기본 전액, 회차권은 제안액)·환불일(기본 오늘, 마감된 달이면 거부)·사유 입력 → `validateRefund` → `PaymentStore.save(buildRefundRow(...))`.
2. 전액 환불 + 회차권이면 회차권 완료 처리(notes 줄 `[날짜] 결제 환불로 종료`) — 지금 흐름 재사용.
3. 제품 판매 취소: 결제 상태 뒤집기 → 환불 행 생성으로 교체(재고 복구는 그대로).
4. 결제 목록: 환불 행 배지("환불 ← 10/5"), 원 결제 행에 "환불 N원 처리됨". "이달 환불 처리" 보조행 = 환불 행 합.
5. 마감 요약·대시보드 문구만 확인(집계는 그대로).
6. E2E: 10월 결제 → 11월 부분 환불 → 10월 매출 불변·11월 매출 차감·엑셀 합계·고객 누적액·마감 잠금과의 상호작용.

## 5. 오너에게 묻는 것
- **B 로 가도 되는가?**(권장) — 세무·정산 관점에서 "환불은 환불한 달의 숫자" 가 맞는지 세무사 확인 1회 권장.
- 회차권 부분 환불의 **위약금율 기본값**(0% / 10% / 매장 설정) — `suggestedProgramRefund(penaltyPct)` 가 받는다.
- 옛 환불(상태 뒤집기) 데이터를 **이관할지**(권장: 이관 없음, 읽기 호환).
