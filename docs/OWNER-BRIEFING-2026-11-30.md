## 6. 알려진 한계 (지점에 그대로 적혀 있는 것)

- **발송·캠페인 성과는 추정**입니다 — 창 안에 예약·결제가 있었다는 사실만 보여 주고 "이 문자 때문" 이라고 말하지 않습니다.

- **중복 결제 경고는 이 PC 결제만** 봅니다(서버 멱등키는 승인 선행).
- Supabase 폴백 프로젝트는 **2026-11-17 에 소멸**을 확인했습니다 — 코드 제거는 로드맵 P1(코어 편집이라 승인 1번).
- 남은 미참조 화면 칸 5개는 전부 **서버·승인·앱 런타임이 선행**입니다(어드민 AI·AI 사용량·지점 PIN 초기화·NAS 거부 띠·모바일 업데이트 띠).

## 7. 릴리스 절차 (v1.0.64) — `release:run` 의 실제 단계

`npm run release:run` 하나가 아래를 순서대로 합니다(`--list` 로 단계 목록만 볼 수도 있습니다). 손으로 할 일은 **0번(버전 올리기)과 머지**뿐입니다.

| 단계 | 하는 일 | 멈추는 경우 |
|---|---|---|
| preflight | main 브랜치·작업 트리 깨끗·`.env.local` 없음·**릴리스 노트 첫 줄 = package.json 버전**·태그 중복 없음 | 하나라도 어긋나면 **아무것도 하지 않고** 멈춥니다(그래서 0번이 먼저입니다) |
| checks | `release:checks` — 서버 테스트·라우트·규칙 커버리지·화면 칸 커버리지·기록 검증·e2e 타입·배포 불변·릴리스 노트·업데이터·outbox·**전체 Playwright** | 하나라도 실패하면 멈춥니다 |
| build | 설치형·포터블 exe | |
| markers | **app.asar 에서** NAS 주소가 있고 Supabase 흔적이 없는지(포터블 exe 는 7z 압축이라 직접 검사가 오탐) | v1.0.34 실사고를 막는 자리 |
| portable | 포터블 업데이트 매니페스트(해시·노트 포함) | |
| mobile | 모바일 번들·매니페스트 | |
| github | GitHub Release 생성·자산 업로드 | |
| channel | NAS 업데이트 채널 게시(해시 대조 뒤 원자 교체) | 지점이 자동으로 받는 자리 |

**포터블 exe 와 폴더형 zip 양쪽이 직전 버전에서 인앱 업데이트로 도달해야 합니다** — 필독 문서는 `DISTRIBUTION-POLICY.md`(필수 점검 목록). 자동 검사(`check:distribution`·`publish-nas-channel`·`verify:nas`)가 매니페스트 필드·해시·내려받기 응답을 대조하지만, **매니페스트에 필드 자체가 없으면 그 줄은 조용히 건너뜁니다**(v1.0.39 폴더형 실사고와 같은 종류) — 채널 게시 뒤 `latest.json` 에 `url`·`zipUrl`·`installerUrl` 이 **모두 있는지** 한 번 눈으로 확인하세요.
