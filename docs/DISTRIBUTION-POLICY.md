# 배포 불변 원칙 — 재다운로드 절대 금지 (오너 상시 지시, 2026-07-30)

> **사용자(매장)가 설치파일을 다시 다운로드하게 만드는 상황은 어떤 릴리스에서도 절대 발생해서는 안 된다.**
> 설치는 매장당 평생 1회. 이후 모든 변경은 프로그램 안 자동 업데이트로만 전달한다.

## 규칙

1. **모든 릴리스는 직전 버전에서 인앱 업데이트로 도달 가능해야 한다.**
   포터블 exe 설치와 폴더형(win-unpacked zip) 설치 **두 경로 모두**.

2. **릴리스 완료 보고 전 필수 검증 (하나라도 실패 시 릴리스 미완료):**
   - [ ] `latest.json`에 `url`+`sha256`(포터블)와 `zipUrl`+`zipSha256`(폴더형) 모두 존재
   - [ ] 두 다운로드 URL 모두 HEAD 200
   - [ ] 채널 파일 sha256 == 스테이징 sha256 (양쪽 다)
   - [ ] `history.json` 최신 버전 일치

3. **업데이트 메커니즘 자체를 바꿀 때는 하위호환 브리지 필수.**
   구버전 클라이언트가 "새 메커니즘을 도입한 버전"까지는 기존 메커니즘으로 업데이트될 수 있어야 한다.
   ⚠️ 실사고: v1.0.39 폴더형에는 zip 업데이트 경로가 없어서 v1.0.40으로 가는 수동 설치 1회가 발생했다(오너 질책). 같은 실수 재발 금지.

4. **매니페스트(latest.json) 필드는 추가만 허용.** 제거·개명 금지 — 구버전 파서가 깨진다.

5. **신규 설치 안내는 배포 사이트로만**: https://crm-update.mkcorp.familyds.com/
   파일을 직접 전달하지 않는다(구버전 파일이 돌아다니는 원인). 사이트 링크는 항상 최신을 서빙한다.

6. **매장에 "다시 받아라"는 안내는 장애 대응에서도 최후 수단.**
   실행 문제는 프로세스 종료·캐시 정리·기존 파일로 해결을 우선하고,
   재다운로드가 불가피했다면 그 원인을 이 문서의 재발 방지 규칙으로 추가한다.

## 근거 구조 (v1.0.40 확립)

- `electron/portable-updater.cjs`: 포터블=단일 exe 교체 / 폴더형=zip 전체 덮어쓰기(Expand-Archive) 자동 적용
- `scripts/prepare-portable-update.mjs`: 빌드마다 포터블 exe + win64 zip을 스테이징하고 매니페스트에 양쪽 sha 기록
- DSM `CRM-publish-update`: exe·zip·매니페스트·사이트를 채널에 게시 (TAG 한 줄만 갱신)
